1. Spesifikasi Teknologi Frontend

Antarmuka (frontend) dari Sistem Informasi Pramuka SMPN 2 Katapang dirancang dengan performa modern menggunakan stack berbasis React dan Server Side Rendering (SSR). Berikut adalah teknologi dan library utama yang digunakan pada modul frontend:

Teknologi / Library Versi Kategori Fungsi Utama dalam Project
Next.js (App Router) 16.2.10 Framework Menangani routing, rendering (hybrid SSR & ISR), server actions, dan optimasi pemuatan halaman.
React 19.2.4 Core Library Penyusunan UI berbasis komponen deklaratif dengan integrasi React Server Components (RSC).
Tailwind CSS ^4.0.0 Styling Framework Framework styling utility-first untuk desain responsif dengan sistem variabel warna terpadu.
GSAP (GreenSock) ^3.15.0 Animation Digunakan untuk ScrollTrigger horizontal timeline kegiatan dan efek reveal teks di landing page.
Framer Motion ^12.42.2 Animation Menangani transisi mikro, animasi toggle modal detail, dan exit-animations (AnimatePresence).
Lucide React ^1.23.0 UI Icons Menyediakan ikon vektor SVG modern yang responsif dan dapat di-style lewat class Tailwind.
@supabase/supabase-js ^2.110.0 Database SDK Koneksi langsung ke database Supabase untuk operasi select/insert pada server components.

3. Sistem Routing & Daftar Halaman

Aplikasi menerapkan File-Based Routing bawaan Next.js. Folder dengan nama bertanda kurung seperti (dashboard) bertindak sebagai Route Group, yang mengelompokkan halaman secara fungsional tanpa memengaruhi struktur URL, serta memungkinkan pembagian Layout yang berbeda untuk Admin dan Siswa.

Daftar Halaman dan Rincian Fungsinya:

  1. Landing Page (/): Halaman depan publik. Menampilkan deskripsi Gudep Satria Batara, data statistik keanggotaan (Siswa, Pembina, Pengurus), horizontal scrolling timeline kegiatan pramuka, dokumentasi prestasi terbaru, galeri dokumentasi foto, dan formulir hubungi kami (hubungi admin). Halaman ini memanfaatkan Incremental Static Regeneration (ISR) dengan interval revalidasi 60 detik untuk performa loading maksimal.
  2. Halaman Login (/login): Halaman form kredensial. Memvalidasi email dan password pengguna. Menggunakan cookies HttpOnly untuk menyimpan token JWT sesi setelah login sukses.
  3. Panel Dashboard Admin (/admin): Menampilkan metrik agregat data (Total Siswa, Log Absensi Sukses, Agenda Kegiatan Aktif) dalam bentuk Bento Grid, dilengkapi chart visual tren tingkat kehadiran anggota latihan dalam 6 agenda terakhir, serta log aktivitas presensi terbaru.
  4. Kelola Absensi Admin (/admin/absensi): Halaman CRUD agenda absensi. Admin dapat membuat agenda absensi baru lengkap dengan parameter lokasi GPS (latitude, longitude) yang dipilih menggunakan Map Picker, menentukan waktu mulai dan radius toleransi.
  5. Input Penilaian SKU (/admin/penilaian): Halaman penilaian siswa. Admin/Pembina dapat menginput skor pencapaian Syarat Kecakapan Umum (SKU) siswa per regu/kelas.
  6. Panel Dashboard Siswa (/siswa): Halaman utama siswa. Menampilkan status presensi latihan hari ini, informasi regu, serta pintasan menuju fitur absensi dan rapor.
  7. Halaman Absensi Siswa (/siswa/absensi): Halaman check-in berbasis lokasi GPS. Mengambil koordinat perangkat siswa, memverifikasi jarak dengan radius geofence agenda yang aktif, dan mengirimkan log kehadiran secara real-time.
  8. Halaman Raport SKU Siswa (/siswa/sku): Menampilkan visualisasi grafik pencapaian nilai SKU siswa dalam bentuk radar/bar chart untuk memonitor perkembangan kompetensi kepramukaan mereka.

4. Deskripsi Visual Antarmuka (UI)

Desain antarmuka aplikasi mengusung tema Aesthetic Vintage-Scout dengan pendekatan premium. Palet warna dikurasi secara harmonis untuk merepresentasikan identitas pramuka (hijau hutan dan warna cokelat kayu) yang diaplikasikan secara modern:

  • Warna Latar Belakang (Warm Vintage Paper): Menggunakan warna dasar krem hangat (#FBF9F6) yang memberikan kesan klasik seperti kertas dokumen pramuka lama, dipadukan dengan aksen border tipis cokelat susu (#D1C9BC).
  • Warna Utama (Forest Green): Warna hijau hutan gelap (#1E3F20) digunakan sebagai identitas warna utama (Buttons, Headers, Active States) yang memberikan kesan formal dan berwibawa.
  • Warna Aksen (Golden Amber): Warna kuning keemasan (#D97706) digunakan untuk menonjolkan bagian interaktif penting seperti lencana prestasi, status aktif, atau tombol konfirmasi utama.
  • Tipografi Premium: Judul besar menggunakan font Serif (Playfair Display / Georgia) untuk memberikan nuansa akademis dan berkelas. Teks isi menggunakan font Sans-serif (Outfit / Inter) yang bersih, sedangkan log status/angka metrik menggunakan font Monospace (JetBrains Mono) untuk kesan data presisi.

Deskripsi Struktur Bento Grid Dashboard Admin:

Dashboard admin ditata menggunakan layout Bento Grid CSS Grid. Kartu-kartu statistik dirancang dengan tinggi seragam (h-48), berlatar belakang putih bersih dengan sudut membulat lebar (rounded-3xl). Terdapat efek mikro-interaksi di mana batas tepi kartu akan berubah warna menjadi kuning emas (hover:border-accent) secara halus saat kursor melintas.

Penerapan Animasi (GSAP & Framer Motion):

Aplikasi menggunakan kombinasi library animasi terkemuka untuk menghidupkan antarmuka:

A. Animasi GSAP ScrollTrigger (Landing Page):

GSAP bertugas mengontrol transisi horizontal timeline kegiatan pada desktop. Ketika pengguna men-scroll halaman ke bawah secara vertikal, timeline kegiatan akan terkunci (pinned) dan bergeser secara horizontal ke samping kiri (translate XPercent) sejauh 50% untuk menampilkan kartu kegiatan secara berurutan. Statistik kuantitatif (angka siswa, pembina) juga dianimasikan bergerak menghitung dari angka 0 ke nilai aktual (Counter Animation) menggunakan properti innerText snap.

B. Transisi Framer Motion (Modals & Cards):

Framer Motion digunakan untuk modal interaktif detail kegiatan/prestasi. Saat kartu kegiatan diklik, modal pop-up akan muncul dengan transisi skala (scale: 0.95 -> 1) dan opasitas (opacity: 0 -> 1) yang smooth. Ketika ditutup, AnimatePresence memastikan animasi keluar berjalan mulus sebelum modal benar-benar di-unmount dari DOM.

5. Kode Sumber (Source Code) Utama Frontend

Berikut adalah cuplikan kode implementasi Server Action pada frontend Next.js yang menangani proses check-in absensi geografis siswa secara aman: 

// Source File: frontend/src/app/actions/absensi.ts
'use server';

import { supabase } from '@/lib/supabase';
import { getSession } from '@/lib/session';
import { calculateDistance } from '@/lib/gps';
import { revalidatePath } from 'next/cache';

export async function checkInAction(payload: {
  siswa_id: number;
  agenda_id: number;
  latitude: number;
  longitude: number;
}) {
  const session = await getSession();
  if (!session) {
    return { success: false, error: 'Sesi habis. Silakan masuk kembali.' };
  }

  try {
    // 1. Ambil detail koordinat agenda absensi
    const { data: agenda, error: agendaError } = await supabase
      .from('agenda_absensi')
      .select('*')
      .eq('id', payload.agenda_id)
      .maybeSingle();

    if (agendaError || !agenda) {
      return { success: false, error: 'Agenda absensi tidak ditemukan.' };
    }

    if (agenda.status === 'nonaktif') {
      return { success: false, error: 'Agenda absensi ini sudah tidak aktif.' };
    }

    // 2. Kalkulasi jarak koordinat GPS siswa menggunakan rumus Haversine
    const distance = calculateDistance(
      payload.latitude,
      payload.longitude,
      agenda.latitude,
      agenda.longitude
    );

    // 3. Validasi radius maksimal geofence
    if (distance > agenda.radius) {
      return {
        success: false,
        outOfRadius: true,
        error: `Jarak Anda: ${Math.round(distance)}m, Maksimal: ${agenda.radius}m.`,
      };
    }

    // 4. Catat kehadiran ke database
    const { data: absensi, error: saveError } = await supabase
      .from('absensi')
      .insert([
        {
          siswa_id: payload.siswa_id,
          agenda_id: payload.agenda_id,
          latitude: payload.latitude,
          longitude: payload.longitude,
          jarak: parseFloat(distance.toFixed(2)),
          foto_absen: 'hadir' // status kehadiran disimpan di kolom foto_absen
        },
      ])
      .select('*')
      .single();

    if (saveError) throw saveError;

    // Refresh halaman untuk meng-update UI log kehadiran
    revalidatePath('/siswa');
    revalidatePath('/siswa/absensi');
    
    return { success: true, data: absensi };
  } catch (error) {
    console.error(error);
    return { success: false, error: 'Gagal memproses absensi.' };
  }
}

Penjelasan Logika Kode: Direktif 'use server' menandakan bahwa fungsi ini dieksekusi secara eksklusif di server-side (Next.js Server Action), mencegah leak Supabase credentials ke client. Fungsi menerima data identitas siswa, agenda, serta posisi koordinat perangkat. Setelah memvalidasi sesi aktif, koordinat diverifikasi dengan data agenda. Jika berada dalam batas radius, log kehadiran akan ditulis ke database PostgreSQL, lalu server melakukan revalidatePath untuk membersihkan cache halaman terpengaruh agar data absensi terbaru langsung merender di sisi client.
